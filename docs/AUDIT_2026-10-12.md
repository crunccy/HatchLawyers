# Bug / exploit audit — 2026-10-12

A read-through of every server-side script in `src/` (PlayerData, ShopService, CaseService, LawyerService,
EggServer, PrestigeService), looking for ways to lose progress, dupe things, or get something for nothing.
Cloud session: **none of this is in Studio yet** — a local session pastes the changed files in (they are mirrors;
Studio is the source of truth, so diff against Studio first in case mr.robe changed one since).

## Fixed (on branch `claude/sharp-dirac-02vssj`)

| # | Where | What could happen | Fix |
| --- | --- | --- | --- |
| 1 | `PlayerData` getStore / load / write | **Serious.** On a live server, ONE failed DataStore probe (a Roblox outage blip) turned the whole server "memory only" forever: everyone who joined after got a fresh, empty firm instead of their own, and nothing they did there was saved. Worse, `saveNow` then returned `true`, so `ShopService` granted Robux products and told Roblox they were processed without them ever being saved. | Only Studio falls back to memory-only. A live server retries the store (`LOAD_ATTEMPTS`), kicks with a friendly "please rejoin in a minute" if it still can't load, and `write` reports failure, so a purchase stays `NotProcessedYet` and Roblox retries it later. |
| 2 | `PrestigeService` | `BadgeAwards.award` ran between `Prestige.Level += 1` and the reset. Badge calls yield and can throw: a throw left the player with the new Supreme level **and** their coins, offices and firm (a free prestige). | Badge award is `task.spawn`ed. |
| 3 | `EggServer` | Same badge call after the coins were spent but before the lawyer was added: a throw = coins gone, no lawyer. A yield delayed the hatch. | `task.spawn`ed. |
| 4 | `CaseService` resolveCase | Badge calls inside the payout: a throw skipped the goals and the `CaseResult` the client waits on (office looked stuck). | `task.spawn`ed. |
| 5 | `LawyerService` mergeSelected | Iterated the whole client-sent table, so a hand-made `{a, b, c, x = d}` merged a 4th lawyer away. Self-harm only, but sloppy. | Only `picks[1..MergeCount]` are used. |

All five compile (`tools/checks/run_checks.py`).

## Checked and sound
- **Robux:** products are granted only in `ProcessReceipt`, once per PurchaseId, and only acknowledged after a
  successful save (now really — see #1). Passes are read through `ShopService.effect`.
- **Remotes:** every handler (`AssignClient`, `PlaceLawyer`, `TrainLawyer`, `MergeLawyers`, `MergeSelected`,
  `CancelLawyerChange`, `Prestige`, `MarkSkinsSeen`) type-checks its arguments, checks ownership by uid / office
  index, is throttled, and computes every amount on the server. Nothing trusts a client number.
- **Eggs:** price, unlock tier, max-owned, cooldown, pity and rolls are all server-side; the cooldown is set
  before any yield, so a double prompt can't roll twice. Config checks now guarantee every egg has a lawyer for
  every rarity it can roll (a missing one would have errored *after* taking the coins).
- **Cases:** lawyers on a case can't be moved (changes are queued), payouts come from Config + Formulas only.

## Needs a decision (not changed)
1. **Robux shop vs the MVP rule.** `Config.Shop` sells coin packs (CashSmall / Medium / Large) and "3 Rare Eggs"
   for Robux, and Double Cash / Lucky Eggs passes. CLAUDE.md says *"MVP: no Robux for coins, eggs or power."*
   Either the rule is out of date (then update CLAUDE.md) or those products should be switched off before launch.
   Also worth knowing for a young audience: Roblox requires showing odds for paid random items — the Rare Egg
   token is a fixed Rare, so it's fine; Lucky Eggs changes odds, so the odds board should show the boosted odds
   to pass owners (it currently shows the base odds).
2. **"Supreme" means two things:** the top rarity (Supreme lawyers) and prestige ("go Supreme", Supreme level).
   Kids will mix them up ("I got Supreme!"). Suggest renaming prestige to e.g. "Empire" (the code already calls it
   Supreme Empire) — a text change in the Supreme panel / HUD only, no save change.

## Small notes (no fix needed now)
- `GoalService.track(player, "train", bought)` passes a count; GoalService is Studio-only — check it uses it
  (otherwise "upgrade 10 times" goals count a 10-level max-buy as 1).
- `PlayerData.sync` JSON-encodes the whole lawyer list into an attribute on every coin change. Fine at 50
  lawyers; if `MaxOwned` grows a lot, sync the list only when lawyers change.
